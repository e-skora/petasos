## 0. Terms used here

- **Owner API**: the browser-facing HTTP endpoints under `/owner/`, served by `petasos.owner`. They are the second front door to the same `Gate`, `GrantStore`, `Executor`, and `Ledger` the MCP tools use (ARCHITECTURE.md section 3). Despite the name, several of them are open to every role; the name says who the surface was built for.
- **Bearer string**: as in 003: `Authorization: Bearer <id>.<secret>`, one of the three tokens `POST /session` returns.
- **Browser origin**: the `Origin` request header a browser sends on a cross-site request. The demo app at `https://petasos.io/demo/` calls `https://api.petasos.io`, so every call it makes is cross-site and carries one.
- **Preflight**: the `OPTIONS` request a browser sends before a cross-site request that carries an `Authorization` header, asking whether the real request is allowed.
- **Origin gate**: the ASGI (the Python web server interface every layer here speaks) layer in `owner/origins.py` that answers preflights, refuses unknown origins, and adds the cross-origin response headers. It wraps only `/session` and `/owner/*`. It is hygiene for browsers, not the API's protection: the bearer string is what protects every endpoint.
- **Card**: the JSON an approver sees for one waiting grant. Over MCP it is the 003 card (grant id, token, verb, tier, expiry, the action record). Over the owner API it is that card plus the ticket's customer name and subject and a server-built plain summary.
- **Service module**: `mcp/service.py`, new in this change, holding the call logic both front doors share (argument shape check, role tool sets, the MCP card, approve-then-run), moved out of 003's `mcp/tools.py` and `mcp/server.py` without changing behaviour.
- **Ledgered read**: a ticket read that goes through `Gate.propose` as an L1 action and so writes one `READ` ledger row, exactly as the MCP `list_tickets` and `get_ticket` do (003 spec 3.18).

## 1. Decisions for this change

Identity, origins, and bounds

| # | Decision | Choice | Why |
|---|---|---|---|
| 4.1 | Authentication on `/owner/*` | Every `/owner/*` request carries a bearer string. `owner/auth.py`: `identity_for(request, *, registry, clock) -> Identity` reads `Authorization`, requires the scheme `Bearer` exactly (same parsing as `IdentityMiddleware`: one space, the rest is the bearer string, split at its first dot inside `ClientRegistry.authenticate`, 003 spec 3.2), calls `registry.authenticate(bearer, now=clock())`, and on a missing, malformed, unknown, wrong, or expired token raises `Unauthenticated`, which the endpoint returns as `401` with the body of 4.6 and status `refused/unauthenticated` ("Sign in to this demo session first."). On success it sets `request.state.identity = identity`, which writes into the same `scope["state"]` dict `IdentityMiddleware` uses for `/mcp` and the guard seam reads at hit time (003 spec 3.10; the lint pass verified that a route-set identity reaches the seam's ledger row), so a canary hit on an owner route is ledgered with the real actor and scope. `IdentityMiddleware` is unchanged and still guards only `/mcp`. | 003 spec 3.3; invariant 16; the seam's actor rule. |
| 4.2 | Roles per endpoint | The table in 4.5 names, for every endpoint, the roles that may call it. A caller with the wrong role gets `403` with status `refused/not_allowed` (the 003 sentence). The check runs before any quota reservation and before any Gate call; it writes no ledger row. Role is read from `Identity.role`; the `approver` flag is checked again for `approvals`, `approve`, `abort`, and `abort-all` (belt and braces: the store refuses a non-approver a third time). | Invariant 19; 003 spec 3.4 ordering (visibility before quota). |
| 4.3 | Browser origins | `owner/origins.py`: `BROWSER_ORIGINS = frozenset({"https://petasos.io", "https://www.petasos.io", "http://localhost:5173", "http://127.0.0.1:5173"})` (the demo's production origin, its `www` alias, and Vite's dev server; the demo app is served at `petasos.io/demo/` as one Cloudflare Pages project, the answer the planning thread recorded under question 2 of 2026-09-26 in `changes/QUESTIONS.md` on 2026-09-30). `create_app` reads `petasos.owner.origins.BROWSER_ORIGINS` at build time, so a test patches that name before calling `create_app`; the `create_app` signature is unchanged (4.10). `OriginGate(app, *, origins: frozenset[str])`, attribute `app` for the wrapped app, is raw ASGI middleware installed outermost. Non-http scopes (lifespan) pass through untouched. For any http path other than `/session` and paths starting with `/owner/` it passes every message through untouched (so `/mcp` keeps refusing every `Origin`, 003 spec 3.3). For those paths: a request with no `Origin` header passes through untouched (curl, the deploy smoke script, tests); a request whose `Origin` is in `origins` passes through and the gate adds `Access-Control-Allow-Origin: <that origin>`, `Vary: Origin`, and `Cache-Control: no-store` to the downstream `http.response.start`, whatever produced it (a route, a 401, or the guard seam's 409, so the demo app can read the refusal; the lint pass verified the header lands on the seam's replaced start message); a preflight from an allowed origin (`OPTIONS` with an `Access-Control-Request-Method` header, on any of the gated paths) is answered by the gate itself with `204`, an empty body, `Access-Control-Allow-Origin: <origin>`, `Access-Control-Allow-Methods: GET, POST, OPTIONS`, `Access-Control-Allow-Headers: Authorization, Content-Type`, `Access-Control-Max-Age: 600`, `Vary: Origin`, and never reaches the inner app; a request whose `Origin` is not in `origins` (preflight or not) gets `403` from the gate with `content-type: application/json`, `Vary: Origin`, and exactly these bytes as its body: `{"status":"refused/origin","explanation":"This website is not allowed to use the demo's browser endpoints.","tier":null,"verb":null,"grant_id":null}`, and never reaches the inner app. No credentials flag is set (the app sends a bearer header, never a cookie). The preflight and the origin refusal are the only responses this change adds that the guard seam does not scan; both are constants with no application data, and a test asserts their bodies byte for byte. The router is built with `redirect_slashes=False`, so `/session/` and `/owner/tickets/3/` are plain 404s and never a redirect around the gate. | Proposal: name origins and cross-origin handling per endpoint. Invariant 15 (the exemptions are enumerated and constant; ARCHITECTURE.md 0.4 lists them). |
| 4.4 | Order of checks, request bounds, and quotas | Every `/owner/*` request is checked in this order, and the first failure answers: (1) origin (the gate, 4.3); (2) `401` unauthenticated (4.1); (3) `403` role (4.2); (4) body bound: `MAX_OWNER_BODY_BYTES = 16_384`; a `Content-Length` above it gets `413` with status `refused/too_large` ("That request is too large for this demo."); a request with a `Transfer-Encoding` header is read up to `MAX_OWNER_BODY_BYTES + 1` bytes and, if that many arrive, gets `413` too (005's outer layer answers such requests with `411` in the deployed process before this code runs; here the rule keeps the app safe on its own); (5) body shape: the body must parse as a JSON object (catch `ValueError` and `RecursionError` alike) with exactly the top-level keys the endpoint names, string-typed where the endpoint says so, else `400` with `refused/invalid_arguments` (the 001 sentence); (6) quota reservation; (7) the handler. Quotas reuse `sessions.quotas.reserve` in a `BEGIN IMMEDIATE` transaction of their own, keyed by the identity's scope. Every endpoint that runs the Gate (`tickets`, `tickets/{number}`, `propose`) and every approval endpoint (`approve`, `abort`, `abort-all`) reserves family `calls` with `quotas.CALLS_PER_HOUR` and increments `abuse_counters.tool_calls`, exactly as the MCP `tools/call` path does for every admitted call (003 spec 3.21), so a session's MCP and browser actions share one hourly allowance of 120 and one session cannot write more ledger rows through the browser than over MCP; `approvals` and `ledger` (the polled reads, which write no ledger row) reserve family `browser_reads` with `BROWSER_READS_PER_HOUR = 1200`; `ledger/verify` reserves family `verify` with `VERIFY_PER_HOUR = 30` (it walks the whole chain). The two constants are module constants in `owner/api.py`, read as `api.NAME` so tests patch them. Over a limit: `429` with `refused/quota` (the 003 sentence), no ledger row. `GET /owner/me` reserves nothing. Any other path under `/owner/`, or a wrong method on a known path, gets Starlette's default `404` or `405` JSON (no application data); those are not this change's shape and are not documented further. | 003 spec 3.21; PRODUCT.md demo hygiene; the lint pass: the 003 abuse bound must not be widened by the browser. |

## 2. Public interface

```python
from petasos.storage import Database
from petasos.app import create_app
from petasos.owner import owner_routes, OriginGate, MAX_OWNER_BODY_BYTES
from petasos.owner import origins  # origins.BROWSER_ORIGINS, patched in tests before create_app
from petasos.mcp.service import shape_ok, approval_card, approve_and_run, PROPOSABLE_TOOLS

db = Database(tmp_path / "petasos.sqlite")
db.migrate()
app = create_app(db, clock=clock)  # unchanged signature; 005 calls it this way

# Browser (fetch from https://petasos.io/demo/, Origin https://petasos.io):
#   OPTIONS /owner/approvals  -> 204 with the allow headers (never reaches the app)
#   POST /session             -> 201 (003), now with Access-Control-Allow-Origin: https://petasos.io
#   GET /owner/me             Authorization: Bearer <visitor>  -> {"status": "ok", "explanation": "Done.", "tier": null, "verb": null, "grant_id": null, "data": {"role": "visitor", ...}}
#   GET /owner/tickets        as any role  -> data: [ {number, customer, subject, status, amount_minor, currency, version}, ... ]  (one READ ledger row, one calls event)
#   POST /owner/propose       as agent, {"tool": "issue_refund", "arguments": {"ticket": 3, "amount": "42.00", "currency": "USD"}}
#                             -> 200 {"status": "staged", "tier": "L5", "verb": "ISSUE-REFUND", "grant_id": 1, ...}   (no token)
#   GET /owner/approvals      as agent  -> 403 {"status": "refused/not_allowed", ...}
#   GET /owner/approvals      as owner  -> data: [ {grant_id, token, verb, tier, record, expires_at, customer, subject, summary} ]
#   POST /owner/approve       as owner, {"token": "...", "verb": "ISSUE-REFUND"} -> 200 {"status": "executed", ...}
#   GET /owner/tickets/3      -> data: {"ticket": {...}, "notes": [...], "mail": [...], "refunds": [ {amount_minor: 4200, currency: "USD", ...} ]}
#   GET /owner/tickets/7      -> 409 from the guard seam (JSON-RPC-shaped, error.data.status refused/guard_tripped); two ledger rows: the READ, then the refused row with route "owner" and this identity
#   GET /owner/ledger         -> data: [ {id, ts, kind, actor_role, verb, tier, grant_id, code, description}, ... ]
#   POST /owner/ledger/verify -> data: {"ok": true, "rows": 12}
#   GET /owner/tickets  with Origin: https://evil.example -> 403 refused/origin (never reaches the app)
```

Signatures this change adds: `owner_routes(db, *, registry: ClientRegistry, clock) -> list[Route]`; `OriginGate(app, *, origins: frozenset[str])`; `identity_for(request, *, registry, clock) -> Identity` and `Unauthenticated`; `rows_for(conn, *, scope, limit, before) -> list[dict]`; `ticket_activity(conn, *, scope, number) -> dict`; `ticket_meta(conn, *, scope, resource) -> tuple[str, str] | None`; `owner_card(grant, *, meta) -> dict`; `shape_ok(name, arguments) -> bool`; `approval_card(grant) -> dict`; `approve_and_run(gate, *, token, verb, approver) -> Result`. `petasos.owner.__init__` exports `owner_routes`, `OriginGate`, `MAX_OWNER_BODY_BYTES`; `petasos.owner.origins` exports `BROWSER_ORIGINS`.
